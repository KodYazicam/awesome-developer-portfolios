## 📜 Code of Conduct

By participating in this project, you agree to:

- 🤝 Be respectful and considerate
- 💬 Use welcoming and inclusive language
- 🎯 Focus on constructive feedback
- 🌍 Respect differing viewpoints
- 🚫 No spam or self-promotion without quality

## 🚀 How to Contribute

### ➕ Adding Your Portfolio

1. **Fork the repository** - Click the "Fork" button at the top right
2. **Clone your fork** - `git clone https://github.com/YOUR_USERNAME/awesome-developer-portfolios.git`
3. **Create a branch** - `git checkout -b add-your-name`
4. **Add your portfolio** - Add it to the correct category in README.md
5. **Commit changes** - `git commit -m "Add: YourName - Stack"`
6. **Push to your fork** - `git push origin add-your-name`
7. **Submit a Pull Request** - Go to the original repo and create a PR

### 👤 Adding Someone Else's Portfolio

Found an awesome portfolio? You can add it too!

1. Make sure it's not already in the list
2. Follow the same process as above
3. Credit the developer properly
4. Note: Open source portfolios are preferred

### ✏️ Updating Existing Entries

If you notice outdated information:

1. Verify the new information is accurate
2. Update the entry with correct details
3. Use commit message: `Update: DeveloperName - What changed`

### 🐛 Reporting Issues

Found a broken link?

1. [Open an issue](https://github.com/Veleslobo/awesome-developer-portfolios/issues/new)
2. Include:
   - Developer name
   - Broken URL
   - New URL (if known)

## 📏 Contribution Guidelines

### ✅ Portfolio Requirements

**We Accept:**
- ✅ Well-designed developer portfolios
- ✅ Personal websites with good UX
- ✅ Open source portfolios (highly encouraged)
- ✅ Various tech stacks and design styles
- ✅ Creative and unique approaches
- ✅ Portfolios with working links

**We Don't Accept:**
- ❌ Broken or dead links
- ❌ Low-quality or unfinished sites
- ❌ Template-only sites without customization
- ❌ Non-portfolio websites (blogs-only, companies)
- ❌ Sites with inappropriate content
- ❌ Duplicate entries

### 📝 Format Standards

#### Standard Format

```markdown
| [site.com](https://site.com/) | Developer Name | Stack | [🔓](https://github.com/user/repo) |
```

#### With Features

```markdown
| [site.com](https://site.com/) 💎 | Developer Name | Stack | Features | [🔓](https://github.com/user/repo) |
```

#### Icon Usage

| Icon | Meaning | When to Use |
|:----:|---------|-------------|
| 💎 | Exceptional Design | Outstanding design quality |
| 🔓 | Open Source | Has public GitHub repo |
| 🆕 | Recently Added | Added in last 2 weeks |
| 🔥 | Popular/Trending | Well-known in community |
| ✨ | Creative | Unique/artistic approach |
| 🎭 | Animated | Heavy use of animations |
| 🌙 | Dark Theme | Dark mode default |
| ☀️ | Light Theme | Light mode default |
| 📝 | Has Blog | Includes blog section |
| 🌐 | Multi-language | Multiple language support |

### 🎯 Quality Standards

1. **Working Link** - URL must be accessible
2. **Good Design** - Visually appealing and professional
3. **Original** - Not a duplicate entry
4. **Relevant** - Must be a developer portfolio
5. **Correct Category** - Place in the right section
6. **Alphabetical Order** - Within each section

## 🔄 Pull Request Process

### Before Submitting

- [ ] Portfolio link works
- [ ] Design is professional quality
- [ ] Not already in the list
- [ ] Added to correct category
- [ ] Follows format exactly
- [ ] Alphabetically ordered

### PR Title Format

```
Add: DeveloperName - Stack
Update: DeveloperName - What changed
Fix: Description of fix
Remove: DeveloperName - Reason
```

### PR Description Template

```markdown
## Portfolio Details

- **Developer:** 
- **URL:** 
- **Stack:** 
- **Open Source:** Yes/No (link if yes)
- **Category:** 

## Why This Portfolio?
Brief description of why it's awesome

## Checklist
- [ ] Link works
- [ ] Good design quality
- [ ] Not a duplicate
- [ ] Correct category
- [ ] Format is correct
```

### Review Process

1. **Automated Checks** - Link validation
2. **Maintainer Review** - Quality check
3. **Feedback** - You may be asked for changes
4. **Merge** - Approved PRs are merged
